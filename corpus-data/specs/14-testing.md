# 测试规范

## 测试分层

- 单元测试覆盖 utils、composables 等纯逻辑，使用 Vitest。
- 组件测试覆盖公共组件的关键交互与渲染分支，使用 Vue Test Utils。
- E2E 测试覆盖核心用户链路（登录、下单、提单），使用 Playwright，数量克制。

## 用例要求

- 公共函数与公共组件测试覆盖率不低于 80%；核心业务模块不低于 60%。
- 用例命名使用中文描述句："当xxx时，应该xxx"，禁止 test_1 之类的无语义命名。
- 每个用例只验证一个行为；断言必须明确，禁止只跑不 assert。
- 覆盖边界条件：空输入、超长输入、并发、失败分支。

## Mock 与数据

- 网络请求统一在测试中 mock；用例不依赖真实后端与网络。
- mock 数据结构必须与真实接口类型一致，直接 import 类型约束。
- 时间相关逻辑使用 fake timers，禁止 sleep 等待。

## 流程约束

- CI 中测试不通过禁止合并；测试失败必须当天修复或明确降级为工单。
- 修复缺陷时必须先补复现用例，再修复，防止回归。
- 禁止为凑覆盖率写无断言的空转用例。
