# 异常与错误处理规范

## 全局兜底

- 应用必须注册全局错误处理：`app.config.errorHandler` 兜底组件渲染错误，`window.onerror` 与 `unhandledrejection` 兜底脚本与 Promise 错误。
- 路由守卫中捕获导航异常，避免白屏；异步组件加载失败必须提供重试与降级 UI。
- 关键页面使用错误边界组件包裹，失败时展示可恢复的占位界面而非崩溃。

## 异步错误

- 所有 Promise 调用必须处理失败：try/catch 或 `.catch`，禁止裸调用无 catch 的异步函数。
- catch 之后必须区分处理：可恢复的提示用户并允许重试；不可恢复的上报后进入兜底流程。
- 禁止空 catch 吞错；确需静默必须注释原因并保留日志上报。

## 用户提示

- 错误提示面向用户可理解，禁止直接透出堆栈、原始错误码或英文异常信息。
- 提示分级：toast 用于操作反馈，页面级占位用于数据加载失败，弹窗用于阻断性错误。
- 相同错误在短时间内合并提示，禁止连续重复 toast。

## 上报与追踪

- 错误上报必须包含：错误信息、堆栈、路由、用户标识（脱敏）、版本号。
- 上报请求自身失败不得再触发上报，避免死循环。
- 关键链路（登录、支付、提单）的异常必须打标，支持按链路检索。
