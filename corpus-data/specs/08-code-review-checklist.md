# 代码审查清单

## 审查流程

- MR 发起后 24 小时内必须完成首次评审；评审以规范条款为依据，不做主观风格之争。
- 评审意见分三级：`blocker`（必须修复）、`suggestion`（建议采纳）、`question`（需要澄清）。
- 作者对每条意见必须回复：修复、说明或转为工单跟进。

## 通用检查项

- 命名是否符合命名规范，是否存在魔法数字与未收敛的字面量。
- 是否存在重复代码可提取为函数、composable 或公共组件。
- 错误处理是否完整：异步调用是否有 catch、边界状态（空/加载/失败）是否覆盖。
- 是否遗留调试语句（console、debugger）与注释掉的死代码。

## 安全检查

- 用户输入渲染必须防 XSS：禁止 `v-html` 直接渲染未消毒内容。
- 敏感信息（密钥、token、内网地址）禁止硬编码与打印日志。
- 接口权限校验以服务端为准，前端拦截仅作体验优化。

## 性能检查

- 大列表是否使用虚拟滚动；频繁变更的引用类型是否需要浅响应。
- 是否引入了不必要的大依赖；图片是否懒加载并指定宽高。
- 首屏路由是否懒加载；关键链路是否新增了串行请求。

## 提交回复规范

- 评审通过方可点击批准；blocker 未清零禁止合并。
- 修改后必须 re-request review，禁止静默改动他人已批准的代码。
